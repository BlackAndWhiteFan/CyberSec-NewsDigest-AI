_# CyberSec NewsDigest AI_

An automated cybersecurity news digest built with Python, GitHub Actions, RSS feeds, and planned AI-powered content processing.

## Project Goal

CyberSec NewsDigest AI is designed to collect cybersecurity news from selected RSS feeds, identify relevant articles, generate concise summaries, and deliver a daily digest to Discord.

The project aims to operate with a budget of 0 PLN by using free service tiers wherever possible.

### Current Implementation

- Retrieves RSS or Atom entries from eleven cybersecurity news sources: Polish (Niebezpiecznik, Sekurak, Zaufana Trzecia Strona, CyberDefence24, CERT Polska, Kapitan Hack) and English (BleepingComputer, The Hacker News, SecurityWeek, The Record, Krebs on Security). Entries older than 3 days are skipped, so a new source does not send its whole archive.
- Extracts article titles, links, and descriptions, decoding HTML entities left in feed titles.
- Skips entries with missing titles or invalid URLs.
- Detects duplicate links within a single run and tracks the feeds in which an article appears.
- Maintains persistent article history in `data/seen_articles.json`, separating previously seen links from published links.
- Filters out articles whose links are already recorded in `published_links`, rather than excluding every previously seen article.
- Categorizes articles into critical news, vulnerabilities, and Poland-related news using English and Polish keywords written as word stems; Polish stems were checked against inflected forms generated by the Morfeusz 2 morphological analyzer.
- Assigns priority scores (critical +3, vulnerabilities +2, Poland +1) and subtracts 2 points from titles written in an event, report, or advice context (e.g. conferences, experts, how-to guides, resilience, regulatory fines).
- Excludes promotional titles (webinars, free trainings, e-books, discounts, sponsored content, lectures, sign-ups).
- Selects up to 20 articles with a score of at least 2, so Poland-related articles without a security signal are not selected and the digest may contain fewer than 20 articles.
- Limits each source to 4 articles (Niebezpiecznik: 2, SecurityWeek and The Record: 3, so that frequent English sources do not push out Polish ones); limits are configured in `src/article_selection.py`.
- Sends the digest to a Discord channel through a webhook, grouped by each article's most important category, with clickable titles and source domains, split into messages within Discord's length limit.
- Records links in `published_links` only after a successful delivery; a delivery failure ends the run with an error, so the workflow is marked as failed.
- Archives each delivered article (date, title, link, source, categories, score) in a monthly file `data/archive/YYYY-MM.json`. An archive error is logged and ends the run with an error, but the article history is still saved, so delivered links are not sent again.
- Saves the article history and archive even if the digest step fails, unless the run is cancelled.
- Merges articles about the same event (from different sources, and also from one source when they share a CVE id or a name with digits such as PHP2Shell) into one item with "także:" links to the other sources, and shows articles about events delivered in the last 3 days in a separate "🔁 Ciąg dalszy" section.
- Marks with 🔥 articles about vulnerabilities from the CISA KEV catalog (Known Exploited Vulnerabilities – confirmed exploitation in attacks). The marker is set by code, not by the AI: CVE ids from the title, feed text and article page (also of articles merged into the same event) are compared with the catalog downloaded on every run (`src/kev.py`); the weekly and monthly tops check the saved CVE ids again with the current catalog. Without access to the catalog the digest is sent without markers.
- On the first day of each month, sends the top 10 events of the previous month to a separate Discord channel, and on Mondays the top 5 events of the previous week to `#top-tygodnia` (ranked by number of articles, then sources and score), with AI summaries. Each top has four start attempts and is sent only once (marker `data/last_top.json`).
- Adds a concrete AI summary in Polish (2–3 sentences; 1 sentence when the material is only a title or a short teaser) to each article (Groq: `gpt-oss-120b`, fallback `qwen3.8-27b`), based on the full feed text or the RSS description; when the feed gives fewer than 600 characters, the article text is fetched from its page (`src/article_pages.py`, paragraphs without menus, ads and footer; a page error never stops the digest). Terms must follow the glossary `data/glosariusz_mirror.csv` (a mirror of the CyberSec Mozaika glossary): a summary that breaks it is sent back for correction and then dropped. The same check (`src/summary_quality.py`) rejects filler phrases ("co podkreśla wagę…"), relative time words ("jutro", "dziś"), uninflected terms after a preposition ("przed exploit") and numbers or CVE ids that are not in the article; sentence capitalization is fixed by code; explanations in parentheses are added by code at the first occurrence of a term in the digest, only for 6 chosen terms (e.g. ransomware, exploit, podwyższenie (eskalacja) uprawnień), in the same case as the term ("przed exploitem (kodem wykorzystującym podatność)"). Since v29 the summaries also go through a language check: English summaries, calques from the editable style list `data/styl_unikaj.csv` ("rekordy" → "dane", "AI-zarządzany" → "zarządzany przez AI") and summaries that only restate the title go back for correction, and a separate proofreading round by the second model fixes grammar without changing facts. "Weekendowa lektura" gets a fixed description instead of an AI summary; English roundups (ThreatsDay, Weekly Recap, In Other News) are left out. Without the `GROQ_API_KEY` secret the digest is sent without summaries.
- Continues processing when an individual RSS feed fails.
- Displays diagnostic information about retrieved, skipped, and processed entries, as well as article selection.
- Runs unit tests before executing the RSS ingestion script.
- Uses GitHub Actions to commit and push changes to the persistent article history when that file changes.

The main trigger is an external alarm clock: cron-job.org calls the GitHub API (workflow_dispatch with the `budzik` input) at 06:17 Polish time, Monday to Saturday, and the tops on Monday (weekly) and on the 1st of the month (monthly) at 08:17. It uses a fine-grained PAT limited to this repository and the Actions permission (Read and write), stored only in cron-job.org; the token must be renewed before it expires after one year. GitHub's schedule (attempts at 06:17, 07:17, 08:17 and 09:17, `Europe/Warsaw`) stays as a backup, because GitHub skips or delays many scheduled runs. The first completed alarm-clock or scheduled run sends the digest and later runs that day end without sending (marker `data/last_digest.json`). The workflow can also be triggered manually through GitHub Actions (leave `budzik` unchecked) – manual runs are never blocked and also count as today's digest. A concurrency group prevents two runs from overlapping.

### Important History and Selection Limitations

`seen_links` records links encountered during RSS ingestion. It does not mean that an article has been published.

`published_links` records links successfully delivered to Discord. Articles already recorded there are excluded from subsequent selections.

The current implementation does not persist complete article content as a backlog. Therefore, an eligible article that disappears from the RSS feeds before being selected may no longer be available for a later digest.

Priority scores are keyword-based indicators. They do not represent an AI assessment or a guarantee of editorial relevance.

## Architecture

The target processing workflow is:

1. Retrieve articles from configured RSS feeds.
2. Validate article data and detect duplicate links.
3. Update persistent history with newly encountered links.
4. Exclude articles already recorded as published.
5. Categorize eligible articles, calculate priority scores, and exclude promotional titles.
6. Select up to 20 relevant articles for the digest, respecting per-source limits.
7. Generate concise summaries using an AI service.
8. Format and deliver the digest to Discord.
9. Record successfully published links and maintain article history.

GitHub Actions executes the workflow, while Python implements the processing logic. The current implementation covers all steps.

## Configuration and Secrets

Required repository secret (Settings → Secrets and variables → Actions):

- `DISCORD_WEBHOOK_URL` — webhook URL of the Discord channel that receives the digest. It is passed only to the workflow step that runs the digest. Without it, delivery is skipped without an error.
- `DISCORD_MONTHLY_WEBHOOK_URL` — webhook URL of the Discord channel that receives the monthly top 10. It is passed only to the monthly workflow step.
- `DISCORD_WEEKLY_WEBHOOK_URL` — webhook URL of the Discord channel that receives the weekly top 5. It is passed only to the weekly workflow step.
- `GROQ_API_KEY` — Groq API key for AI summaries. It is passed only to the digest step. Without it, the digest is sent without summaries.
- `DISCORD_TEST_WEBHOOK_URL` — webhook URL of the Discord test channel. Runs on branches other than `main` send only there (with a TEST banner) and save nothing; without it they send nothing.

Never commit API keys, Discord webhook URLs, passwords, or other credentials to the repository.
